**Current status:** Synthetic closure done; live acceptance blocked.

## 2. Source / connector scope for Phase C (ACT-007)

**Epic:** C — Ingestion/source connectors  
**Current status:** Backlog; deferred by G1-D4-rev2.

### What is needed

1. **First real source connector scope:** which system(s) will feed the KB first (SharePoint, Confluence, file shares, Git repositories, email archives, etc.).
2. **Representative sample formats:** file extensions, archive layouts, Max/Linux line endings, encodings.
3. **Content sensitivity classification:** which mime types are critical media (images, scanned PDFs, audio/video) and must be OCRed/transcribed before indexing.
4. **Ingestion frequency and volume expectations:** initial load size, daily delta, acceptable lag.

### Why it blocks

Phase C implementation (C.2 connector framework, C.3 parsing pipeline, C.4 content-standard enforcement) cannot be sized or architected without knowing the source landscape. C.1.1 MinIO staging is already done for backup purposes, but real ingestion work is frozen.

### Options

- Select one pilot source (e.g., SharePoint Online or a network file share) and representative formats.
- Keep Phase C in backlog and rely on manual Markdown uploads through the /kb editor until a source is selected.
- Reject Phase C for the first launch and use Git-only content ( GO-managed Spaces ) as the sole source.

### Default if no decision

Phase C remains `backlog`; ingestion is limited to Git-managed Markdown and manual editor uploads.

### Evidence destination

`specs/corporate-kb/adr/adr-source-connector-scope.md` and updated `sprint-status.yaml`.
